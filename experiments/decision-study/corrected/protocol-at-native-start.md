# Preparation/accounting correction protocol

Declared before corrected native timing on 24 November 2026. This is a
post-freeze correction using already observed inputs, not a new untouched
confirmatory experiment. No cycle-model fitting, threshold tuning, dataset
selection or DPU kernel change is permitted in this correction.

The original study remains in the parent directory. Its manifest and raw
archives are immutable. Archived sources are exact copies; their relative
links retain the original path context.

## Corrected interval

Only frequency-based (`hot`) retention builds a permutation and refreshes
reordered values. Identity policies use the existing source values, with no
full-array refresh copy. Their measured refresh interval contains timer and
dispatch overhead. All native intervals still exclude teardown, file output,
synthetic-value generation and application/SDK integration.

Every model decision pays preparation and inspection of all physically
available candidates. Each simple rule starts with the stream512 reference
used for feasibility. Fixed pays its calibration-selected candidate even if
rejected. Capacity pays full retention when physically available. Reuse visits
full (if available), then hot, then batch, stopping at the first accepted
candidate; rejected candidates count. No unavailable full representation is
constructed. Duplicate candidates within a rule count once. The same paths
apply to the unconstrained sensitivity scenario. Dimensions/capacity checks
and simple-rule dispatch are not separately timed. This is accounting for
these implemented candidate representations, not a lower bound for an
optimized analytical inspector that avoids constructing them.

## Execution and acceptance

1. Preserve and verify all 485 historical records and 23,040 scenarios.
2. Rebuild with GCC 15.1.0, `-O3 -std=c++17`; retain host information. Run native
   cases sequentially, 31 samples after three warmups, without concurrent
   simulator execution. Use every distinct preparation needed by all archived
   invocations, including changed values, boundaries and tasklet variants.
3. Independently decode representations and outputs. Compare regenerated
   metadata, feature values, DPU arguments and references byte for byte with
   all archived invocations. Reuse original cycles only if every match passes.
4. Preserve new samples separately. Recompute primary phase timings, the same
   scenario grid, payback, sample envelopes and original success criterion.
   Remeasure Python prediction arithmetic; keep original coefficients and fit
   time explicitly identified as inherited evidence.
5. Replay four representative frozen records, including repeated execution
   and non-default DRAM options. Run native sanitizer and accounting-edge checks.
6. Update the thesis only after verification. Report any changed conclusion;
   neither positive retention nor the failed-selector conclusion is required
   to survive. No new independent workload evidence is claimed.

Host timings remain nonexclusive-machine measurements. Min/max envelopes are
descriptive observations, not confidence intervals. Simulation is not hardware
validation. The cost interval starts from host CSR and loaded device code.
