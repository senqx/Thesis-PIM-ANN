\section{From a conditional result to an execution choice}
\subsection{Scheduling sensitivity}
We add 360 BFS replays over ten reference splits and both footprints, changing one setting at a time: outstanding limits 16, 32 and 128; consecutive candidate batches of at most two or eight, each drained before the next; and the alternative mapper \texttt{ChRaBaRoCo}. The default is reused. A transaction limit bounds uncompleted reads; a batch bounds vectors exposed before a drain. These are separate interventions, not a full factorial study. Hashes and phase maps verify unchanged reads, candidate membership and original-query accounting.

The result prevents a footprint-only rule. At 128 bytes, round-robin changes cycles by \SchedInflightSixteenRRCompact\% with 16 outstanding reads, compared with \SchedDefaultRRCompact\% at the default. Under the alternative mapper it changes cycles by \SchedAlternateMappingRRFloat\% at 512 bytes and \SchedAlternateMappingRRCompact\% at 128 bytes. Sorting's alternative-mapper 128-byte difference is \SchedAlternateMappingSortCompact\%. The full thesis retains every fixed-order effect, paired interval and query-level diagnostic.

\subsection{Training-selected vector fetch}
The optional execution path profiles original, sorted and round-robin fetch on the first 50 training queries, chooses minimum total service cycles and freezes that choice for all 200 held-out queries. Exact ties prefer original, then sorted, then round-robin. The configuration includes placement, footprint, batch limit and memory settings. This adds 420 calibration replays and 140 choices; held-out evaluation reuses the exact matching measured stream. Within each split, calibration and held-out IDs are disjoint. The extension was motivated by already inspected results, so its evaluation remains exploratory despite training-only selection.

A compatible near-memory engine could implement this as a batched vector-gather operation after candidate discovery, retaining original-order distance/state updates. The target must expose the modelled fine-grained requests; this is not an assumed UPMEM interface. A missing or mismatched profile should use original order until reprofiling. Calibration, buffering, dispatch, computation and communication must all be charged in an implementation. The proposal selects among established schedules; its contribution is the measured configuration dependence and held-out evaluation, not a new HNSW search algorithm.
